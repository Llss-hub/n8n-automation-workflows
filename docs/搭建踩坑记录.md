# 搭建踩坑记录

这份文档记录搭建过程中真实遇到的问题和解决办法。都是中国大陆网络环境、n8n 2.42 下的实测结果。

---

## 一、网络与数据源

### 1. Google 全家桶在国内完全不可用

**现象**：n8n 的 Google Sheets 节点无法完成 OAuth，请求 `sheets.googleapis.com`、`oauth2.googleapis.com`、`accounts.google.com` 全部超时。

**结论**：这不是配置问题，是网络不通。不要在这上面浪费时间。

**替代方案**：

| 原本想用 | 换成 |
|---|---|
| Google Sheets | n8n 内置 Data table，或飞书多维表格 |
| Google Drive | 本地文件节点，或飞书云文档 |
| Notion | 飞书多维表格 |

**如果确实必须用 Google**：需要给容器配置代理环境变量后重建容器，之后还要走 Google Cloud 建项目、启用 API、配置 OAuth 回调的完整流程。对新手来说投入产出比很差。

### 2. Docker Hub 拉不动镜像

**现象**：`docker pull n8nio/n8n` 报 `dial tcp ...: connectex: A connection attempt failed`。

**原因**：`registry-1.docker.io` 在国内不可达。

**解决**：使用国内镜像源前缀。

```bash
docker pull docker.m.daocloud.io/n8nio/n8n
```

其他可用源：`docker.1ms.run`、`hub.rat.dev`、`docker.1panel.live`。

**注意**：换源之后已下载的镜像层会按摘要复用，不会重复下载。如果某个源速度卡住，直接换另一个源继续，已下载的部分不会丢。

### 3. 部分域名的 TLS 被中间设备拦截

**现象**：某些接口报 `DEPTH_ZERO_SELF_SIGNED_CERT`。

**解决**：HTTP Request 节点里开启 `Ignore SSL Issues`。但这属于绕过证书校验，**只对确认可信的域名这样做**。

## 二、n8n 节点配置

### 4. Set 节点（Edit Fields）在 3.2 版本有两个隐藏行为

这两个都会导致**静默失败**——节点亮绿勾但结果是错的。

**问题一：`includeOtherFields` 不生效**

控制「是否保留其他字段」的参数在 3.2 版本里叫 `include`，默认值是 `all`（全部保留）。而 `includeOtherFields` 这个参数在 3.2 版本是被隐藏的，写了也没用。

```json
// 3.2 版本正确写法
{ "mode": "manual", "include": "none" }
```

**问题二：值的属性名跟类型绑定**

字段的值不是写在 `value` 里，而是跟 `type` 绑定：

```json
// 错误：值会变成空字符串
{ "name": "标题", "value": "={{ $json.title }}" }

// 正确
{ "name": "标题", "type": "stringValue", "stringValue": "={{ $json.title }}" }
{ "name": "播放量", "type": "numberValue", "numberValue": "={{ $json.stat.view }}" }
```

规则：`stringValue` / `numberValue` / `booleanValue` / `arrayValue` / `objectValue`，取值的属性名就是 `type` 的值。

### 5. Data table 节点需要两部分存储

**现象**：手动在数据库里建了表，节点却报「找不到表」。

**原因**：n8n 的 Data table 由两部分组成，缺一不可。

| 部分 | 位置 | 作用 |
|---|---|---|
| 元数据 | `data_table` / `data_table_column` 表 | UI 里看到的表名和列定义 |
| 物理存储 | `data_table_user_<表ID>` 表 | 真正存行数据 |

**建议**：不要手写 SQL 建表，直接在 n8n 界面里用 Data tables 功能创建，n8n 会同时建好两部分。

**列名和列类型必须与工作流里的映射完全一致**，否则会出现字段写不进去的情况。

### 6. Code 节点里的 `new Date()` 走的是 UTC

**现象**：日报标题里的日期比实际日期早一天。

**原因**：`new Date()` 返回 UTC 时间，`getDate()` 取到的是 UTC 的日期。北京时间凌晨 0 点到 8 点之间会算错一天。

**解决**：手动加 8 小时再取日期。

```javascript
const BEIJING_OFFSET = 8 * 60 * 60 * 1000;
const today = new Date(Date.now() + BEIJING_OFFSET).toISOString().slice(0, 10);
```

**另外注意**：`$now.format()` 在表达式里可用，但在 Code 节点里不可用（`$now` 不是 Luxon 对象）。

## 三、定时触发器

### 7. 必须 Publish 才会自动执行

n8n 2.x 里，只有点了右上角的 **Publish**，定时触发才会真正注册。没发布之前，工作流只是一张图纸，只有手动点 Execute 才会动。

**判断方法**：发布后查看 `workflow_published_version` 表是否有记录，以及执行记录里是否出现 `mode=trigger` 的执行。

### 8. Publish 是按版本生效的

改完工作流必须**重新 Publish**，否则跑的还是旧版本。

### 9. 可视化配置会丢失分钟参数

**现象**：界面上明明显示 Trigger at Minute 是 0，实际执行时间却是 09:30:53 这种奇怪的分钟数。

**原因**：`triggerAtMinute` 参数在保存时丢失，n8n 会用一个根据节点 ID 算出的伪随机分钟数兜底。

```javascript
// n8n 源码里的兜底逻辑
const minute = interval.triggerAtMinute ?? stableInt(nodeKey, 'minute', 0, 60);
```

**解决**：改用 **Custom (Cron)** 模式，写死表达式。

```
0 0 9 * * *     // 每天 09:00:00（秒 分 时 日 月 周）
```

**注意**：Cron 表达式字段在界面里会存成 `=0 0 9 * * *`。开头的 `=` 是 n8n 的表达式标记，运行时会被去掉，不用手动删。

## 四、飞书推送

### 10. 机器人没点保存，token 就是无效的

**现象**：配置页面里已经显示了 Webhook 地址，但发送时报 `19001 incoming webhook access token invalid`。

**原因**：Webhook 地址在点击「保存」之前就已经显示出来，但**保存之前这个 token 是无效的**。

**解决**：点保存。

### 11. 消息被拒时报的是 HTTP 200

**这是最坑的一个。**

飞书在消息被拒绝时仍返回 HTTP 200，错误码藏在响应体里。而 n8n 只看 HTTP 状态码，所以**节点会显示绿勾，但消息根本没发出去**。

| 响应体 | 含义 |
|---|---|
| `{"code":0,"msg":"success"}` | 成功 |
| `{"code":19024,"msg":"Key Words Not Found"}` | 安全设置的关键词不匹配 |
| `{"code":19001,"msg":"...token invalid"}` | token 无效（多半是没保存） |

**教训**：遇到「节点绿了但没效果」，第一件事是去看返回内容，不要相信节点颜色。

**如果想让 n8n 自动报错**：在推送节点后面加一个 IF 节点判断 `code` 是否为 0，不为 0 就抛错。

### 12. 自定义关键词必须出现在消息里

机器人的安全设置如果选了「自定义关键词」，**消息内容必须包含该关键词才允许发送**。

一个机器人可以设置多个关键词，消息含其中任意一个即可。**如果多个工作流共用一个机器人，记得把各自消息里的特征词都加进去。**

更稳妥的做法：给所有通知约定一个统一前缀（例如 `【自动通知】`），关键词只设这一个。

### 13. 自定义机器人只能在电脑端添加

飞书手机 App 的群机器人列表里只有官方机器人，**没有自定义机器人的入口**。必须用电脑客户端或网页版（feishu.cn）操作。

## 五、社区节点安装

### 14. 装社区节点卡在原生模块编译

**现象**：安装 `n8n-nodes-feishu-lite` 时，npm 报 `gyp ERR! find Python`，卡在编译 `isolated-vm`。

**原因**：这个包声明了 `n8n-workflow` 作为 **peerDependencies**，npm 7 以上会自动安装对等依赖，而 `n8n-workflow` 依赖原生模块 `isolated-vm`，需要现场编译。

**n8n 官方是怎么解决的**：读 n8n 源码可以看到，它在安装前会**先把包里的 peerDependencies、devDependencies、optionalDependencies 删掉**，再执行安装：

```
npm install --audit=false --fund=false --bin-links=false \
  --install-strategy=shallow --ignore-scripts=true --package-lock=false
```

**手动安装的等价做法**：

```bash
cd /home/node/.n8n/nodes
npm install <包名> --legacy-peer-deps --ignore-scripts=true \
  --no-audit --no-fund --package-lock=false \
  --install-strategy=shallow --bin-links=false
```

`--legacy-peer-deps` 的作用就是跳过对等依赖，等价于 n8n 的「删掉 peerDependencies」。

**装完别忘两件事**：往 `installed_packages` 表写一条记录，然后重启 n8n。验证方法是 `n8n export:nodes` 导出节点清单，搜索包名。

**更省事的做法**：直接用 n8n 界面的 Settings → Community nodes 安装。前提是容器能访问 `registry.npmjs.org`。

## 六、一句话总结

国内做自动化，最容易踩的坑不是技术，是这三类：

1. **网络可达性**（服务能不能连上）——开工前先实测，别等搭到一半才发现
2. **静默失败**（节点绿了但结果是错的）——关键节点一定要看返回内容，不能只看颜色
3. **参数被吞**（界面显示的配置和实际保存的不一致）——重要的定时和映射逻辑，用显式写法（Cron 表达式、完整 JSON）而不是依赖界面默认值
